# SafeContract AI OCR 평가 정규화 정책 v1

정책 ID: `safecontract-ocr-normalization-v1`

사용자 요청 기준으로 정의한 개발용 평가 정책이다. 실제 OCR 엔진이나 법률 분석은 구현하지 않는다.
사람이 승인한 `sample_contract.json`의 19개 조항은 불변 Ground Truth로 사용한다.
정규화는 메모리에서 평가용 복사본에만 적용하며 원본 JSON·PDF·수정 이력을 덮어쓰지 않는다.

## 두 평가 모드

- **원문 평가(raw):** 저장된 Unicode 코드포인트를 그대로 비교한다. 공백, CR/LF, 기호,
  밑줄, 대소문자, 조합형/완성형 차이를 모두 유지한다. strip, NFC/NFKC도 적용하지 않는다.
- **정규화 평가(normalized):** 아래 8종의 공백만 양쪽 입력에서 모두 제거한다.
  그 밖의 문자는 변환하지 않는다. 두 모드의 CER를 항상 함께 보고한다.

| 제거 허용 문자 | Unicode |
|---|---|
| 일반 공백 | U+0020 |
| 탭 | U+0009 |
| LF 줄바꿈 | U+000A |
| CR | U+000D |
| 수직 탭 | U+000B |
| 폼 피드 | U+000C |
| 줄바꿈 없는 공백(NBSP) | U+00A0 |
| 전각 공백 | U+3000 |

`str.isspace()` 또는 광범위한 정규식으로 대상을 확장하지 않는다.
제로폭 공백 U+200B, BOM U+FEFF, 얇은 공백 U+2009는 제거하지 않는다.
이 정책은 문서 읽기 순서나 표 행·열 순서를 바꾸지 않는다.
공백 제거는 띄어쓰기나 숫자 사이 공백 오류를 숨길 수 있으므로 정규화 점수만으로 정확성을 판정하지 않는다.

## 금지하는 자동 보정

- `₩`와 역슬래시 `\`, `•`와 `Ÿ`는 서로 다른 문자다.
- 가운데점 `·`, `‧`, `․`, `･` 및 각종 따옴표·하이픈은 통합하지 않는다.
- 숫자, 금액, 날짜, 계약기간, 부정 표현을 추정·수정·보완하지 않는다.
- 천 단위 쉼표, 소수점, 괄호, 체크박스, 밑줄을 삭제하지 않는다.
- 미기입 금액·날짜는 채우지 않으며 밑줄 길이를 임의로 변경하지 않는다.
- 조합형/완성형, 전각/반각, 대소문자, 원문 조항 순서를 통일하지 않는다.

OCR 결과와 Ground Truth에 같은 함수·같은 버전·같은 모드를 적용한다.
이전 기호 오류의 사람 승인 보정은 Ground Truth 구축 이력이며, 앞으로의 OCR 출력을
자동으로 동일하게 치환해도 된다는 뜻이 아니다.

## CER 정의

문자는 Unicode 코드포인트 단위로 센다(UTF-8 바이트나 화면상의 글자 묶음 단위가 아님).
삽입 I, 삭제 D, 치환 S의 비용이 각각 1인 Levenshtein 최소 편집 거리로 계산한다.

`CER = (S + D + I) / N`

N은 해당 모드의 Ground Truth 문자 수다. 출력은 비율이며 백분율 표시 시 100을 곱한다.
삽입이 많으면 CER는 1(100%)을 초과할 수 있으며 상한을 적용하지 않는다.
동률 정렬마다 S/D/I 분해가 다를 수 있어 구현은 합계 편집 거리만 반환한다.

- N > 0, OCR 결과가 빈 문자열: 모든 문자를 삭제한 것으로 계산(CER=1).
- N = 0: CER는 `null`(Python None). 양쪽이 모두 비어 있어도 0으로 꾸미지 않는다.
  편집 거리와 `empty_reference`를 별도로 기록한다.
- 정규화 후 Ground Truth가 비게 된 경우에도 같은 규칙을 적용한다.
- 전체 평가는 조항별 편집 거리 합 / 조항별 N 합인 micro CER를 사용한다.
  빈 Ground Truth 조항에서 생긴 삽입도 분자에 포함하고 해당 ID를 따로 표시한다.
  전체 N 합이 0이면 전체 CER도 null이다. 조항별 CER의 단순 평균을 사용하지 않는다.

## 매칭 및 결과 기록

`document_id`, 물리적 PDF `page`, `clause_id`로 평가 범위를 먼저 고정한다.
이번 데이터는 C001~C019의 계약 본문·특약 범위이며 PDF 전체 5쪽의 모든 문장을 뜻하지 않는다.
본문·표 읽기 순서는 저장된 Ground Truth 순서를 따른다. 조항 경계를 연결해 오류를 상쇄하지 않는다.
`evaluate_corpus`는 ID 집합 불일치를 오류로 처리한다. OCR에서 누락된 조항은 해당 ID의
빈 문자열로 전달해 삭제 오류를 반영한다. 추가 OCR 조항은 별도로 탐지·보고하고 평가 집합을
몰래 줄이지 않는다. 문서/페이지 매칭은 호출자가 확인해야 한다.

결과에는 정책 ID, 문서/조항 ID, 입력 파일 해시, raw/normalized 각각의 편집 거리·N·CER,
누락·추가 범위 및 빈 기준 텍스트 여부를 기록한다. 정책 변경 시 버전을 올리고 양쪽을 재평가한다.
CER는 문자 정확도 지표이며 법적 타당성이나 계약 위험도를 나타내지 않는다.
실제 OCR 결과가 아직 없으므로 이번 단위 테스트를 OCR 성능 측정으로 보고하지 않는다.

## 구현 및 실행

구현: `scripts/ocr_evaluation.py` (Python 표준 라이브러리만 사용)
테스트: `tests/test_ocr_evaluation.py`

프로젝트 루트에서 실행:

```bash
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_ocr_evaluation.py' -v
```

```python
from scripts.ocr_evaluation import evaluate
result = evaluate('보증금 ₩ 100만원\n', '보증금 \\ 100만원')
# 공백 차이는 normalized에서만 제거한다. 원화/역슬래시 차이는 두 모드 모두 오류다.
```
